2 경로는 캔버스가 아니라 별도 패널

4 인코딩 규칙 — 채널이 겹치지 않게

색은 종류, 테두리는 신뢰도, 위치는 층, 크기는 규모. 하나의 채널이 두 가지를 말하지 않습니다.

객체채널의미
노드채움 색종류 — API·라우트 / 코드 / 워커·잡 / 데이터베이스 / 외부
테두리확정(실선) · 후보(점선) · 미분석(빗금 + 점선)
가로 위치(레인)시스템 층 — 역할 축 또는 의존 깊이 축
세로 위치연결 관계 (정렬로 암시, 선 없이)
크기규모 (멤버 수, log 스케일)
엣지표시 여부기본 숨김. 선택했을 때만 표출
선 스타일확정(실선) · 후보(점선)
두께가중치 (묶인 원본 링크 수)

6 확정 규칙 10개

  1. 아무것도 사라지지 않는다. 접힌 것도 개수로 남고 면적을 차지한다.
  2. 상한은 상수가 아니라 뷰포트의 함수다. 큰 화면에서 더 보여야 한다.
  3. 밀도가 부족하면 요약 축을 한 단계 올린다. 심볼 → 파일 → 영역.
  4. 펼침은 세로로만. 좌우 레인의 x축은 절대 움직이지 않는다.
  5. 중첩은 최대 3단계. 그 이상은 어느 레벨인지 읽히지 않는다.
  6. 연결선은 기본 숨김. 관계는 정렬로 먼저, 선은 선택했을 때.
  7. 모든 노드는 클릭하면 파일:줄로 간다. 보기만 하고 끝나는 화면은 죽는다.
  8. 도구는 자기 판단을 설명한다. 어떤 축을 왜 골랐는지 화면에 문장으로.
  9. 못 보는 것을 먼저 말한다. 미분석·동적 경계·DB 미연결을 지도보다 앞에.
  10. 전문 용어에는 설명을 병기한다. Repository → "DB를 읽고 쓰는 곳".
