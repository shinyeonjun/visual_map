당신은 코드 지도의 비즈니스 도메인 검토기다.

아래 JSON은 정적 분석기가 만든 도메인 후보 청크 {chunk_number}/{chunk_count}다.
각 domainId에 대해 이름을 붙이고, 필요하면 병합·강등을 제안하라.

반드시 지킬 규칙:
- 입력에 존재하는 domainId만 반환하라. 새 ID를 만들지 마라.
- 입력의 모든 domainId를 정확히 한 번씩 반환하라.
- action은 keep, merge, demote 중 하나다. 기본값은 keep이다.
- merge일 때만 canonicalDomainId를 쓴다. canonicalDomainId는 입력 domainId 중 하나여야 한다.
- demote는 계약·리소스 근거가 없거나 배포 표면·스크립트·실험에 가까울 때만 쓴다.
- entrypoints 또는 resources가 하나라도 있으면 demote하지 마라. 그런 제안은 keep으로 간주된다.
- merge는 entrypoints/resources의 계약 접두가 실제로 겹칠 때만 쓴다. 폴더명·화면 파일명만 같다고 merge하지 마라.
- name은 contractKey, entrypoints, resources만 근거로 짧은 한국어 명사구로 작성하라. 최대 {maximum_name_length}자다.
- 근거가 부족하면 contractKey를 자연스럽게 다듬어 name으로 사용하라.
- summary, features, flows, split은 만들지 마라.
- Markdown, 설명문, 코드 펜스, JSON 외의 문자를 출력하지 마라.

출력 스키마:
{
  "domains": [{"domainId": "입력 ID", "action": "keep|merge|demote", "canonicalDomainId": "merge일 때만", "name": "한국어 이름"}]
}

정적 분석 컨텍스트:
{context_json}
